# Android Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, with one fresh whole-branch review. User said to proceed with the proposed architecture.

**Goal:** Installable Android APK for local camera video, controls and SD-card playback/export.

**Architecture:** Add Kotlin Android shell and Rust protocol crate; LibVLC renders live surfaces; validated XM samples feed native movie export. Existing macOS source remains unchanged.

**Tech Stack:** Rust, Kotlin, Gradle, Android SDK/NDK, LibVLC.

**Spec:** `docs/superpowers/specs/2026-10-26-android-design.md`.

## Global Constraints

API 28 minimum/API 37 target; arm64 and x86_64; English/pt-BR; no vendor binaries, private footage or credentials; retained private release signer; playback temporary until explicit export; hidden video releases decoders; no card delete/format.

## Review Focus

- A reply for a different session/sequence is rejected, including split/coalesced TCP packets.
- Leaving a screen during transfer or movement cancels it without stale UI updates or residual cache/movement.
- HEVC streams remain usable; an H.264-only default is insufficient.
- Settings preserve unrelated concurrent edits and reject edited-field conflicts.
- Stable signature, excluded backups and explicit document exports preserve credentials/privacy across updates.
